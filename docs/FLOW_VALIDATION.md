# 流程驗收紀錄（2026-09-10）

依使用者最新要求：先驗證本機完整流程，再處理雲端後端與新增服務串接。

## 本次已跑通的範圍

以獨立暫存資料庫、三個明確標示 TEST ONLY 的版本，透過真實 HTTP 路由依序執行：

1. 加入 Discogs 版本、記錄需求決策。
2. 更新行情、搜尋平台、解析來源頁、產生待人工核對的配對。
3. 缺成本及匯率時，不產生毛利或可整理草稿狀態。
4. 填匯率、含運進貨成本、預定售價、版本／品相、供貨確認與出貨天數。
5. 計算毛利與淨利，開放建立草稿。
6. 每筆來源建立草稿兩次，更新同一草稿，不重複新增。
7. 勾選三筆草稿，匯出 Quicklister CSV；包含 Vinyl、CD、Cassette，幣別及無封套狀態正確。

此測試替換 Discogs 網路回應、Tower 搜尋頁傳輸與一般 Sheets 寫入；仍執行實際資料解析、資料庫、後台工作、比價及匯出程式。不是三件實際可套利商品的證明。

## 修正與驗證

- 草稿以 source_offer_id 連結來源，重送更新同一筆；不同來源仍可建立不同草稿。舊草稿沒有來源 ID，保留原樣。
- 來源版本與草稿版本不一致時拒絕儲存。
- 報價表單與後端允許 Generic、No Cover、Not Graded 封套狀態；媒體仍須實際評級。
- 73 項後端測試、2 項前端請求測試、型別檢查及 Vercel 靜態建置通過。
- 瀏覽器檢查本機總覽與進貨比價頁：三種格式篩選、缺項提示、未備妥時停用草稿功能正確顯示。未宣稱逐個表單已經由瀏覽器實際送出，完整寫入路徑由 HTTP 測試驗證。

- 正式 Discogs 刊登／批次上架 API：目前終點為本機草稿與 Quicklister CSV；尚未實際匯入或刊登。
- AI 文案與客服尚未串接。
- 搜尋相關商品只是候選，可能包含不同專輯或壓片；不是已驗證的相同商品。需要人工核對版本後才進入可整理草稿狀態。
- 四平台有先前真實抓取紀錄，但本次三格式全流程使用合成回應；不能承諾平台永遠可抓或庫存永遠有效。
- 自動排程有時間／互斥／失敗回報測試，自然到點及長時間運轉仍需觀察；Mac 關閉或休眠時不執行。

## 後續驗收：草稿重新確認

新增五項回歸測試，後端總計 78 項通過。草稿可以依 ID 修改價格與備註，保持單一筆資料；確認超過 48 小時即停止 Quicklister 匯出，重新確認後恢復。來源取消供貨時，即使重存草稿仍拒絕匯出；編輯不能移除既有來源關聯。來源更新後要求再次檢視草稿。畫面與下載端共用同一份缺項檢查，避免前端停留舊狀態仍能下載。

此處的「可匯出」只表示草稿基本資料及來源確認有效，不代表已完成最新行情、匯率與獲利的重新評估，也不是 Discogs 刊登成功。每次進貨決策仍應回比價頁檢視更新後的成本與預估淨利。

## 後續驗收：配對候選品質

新增名稱／編號依據篩選及七項測試。相同歌手的不同專輯不會單靠搜尋命中列入比價表；明確周邊及已知格式衝突排除。日文別名可由 Discogs `=` 分隔名稱匹配；品相差異不影響配對。不同語言且沒有共同名稱／編號的商品可能漏列，需從原始搜尋手動核對。相同專輯的不同壓片仍可能列出，因此不自動勾選版本確認，也不直接刊登。人工報價維持原有資料，未自動刪除。

## 後續驗收：排除／恢復配對

以 HTTP 測試確認排除狀態持久保存；更新報價不取消排除，建立新的 Dashboard 也保留狀態。已排除貨源的既有草稿在下載時阻擋，錯誤訊息指出配對已排除；恢復後可再次通過驗證。排除資料不刪除來源或行情，僅對指定來源連結 × 版本生效。原本候選搜尋結果被替換時，排除列表仍由獨立紀錄建立。

## 後續驗收：批次建立草稿

新增四項測試，直接呼叫與網站相同的 Dashboard 操作入口，確認多筆建立、重複提交不新增／不覆寫人工內容、任一未備妥即無新增、已排除重新檢查及批次上限／無效 ID 驗證。可執行的 75 項測試、前端型別與靜態建置通過。

本次完整測試嘗試有 15 項因作業環境禁止 socket bind 而失敗，並非通過；尚未驗證新版 HTTP 連線流程與瀏覽器批次提交。未停止既有後端程序，避免在無法重新綁定連線時中斷服務；新版後端須於允許本機服務的環境重啟後才可從網站使用。

## 批次 HTTP 處理與交易回復補驗

新增三項純記憶體 HTTP 測試，直接使用正式 BaseHTTPRequestHandler 的請求解析、頁面驗證、路由、JSON 回應；確認報價建立 → 批次建立、重送略過、具體錯誤及缺少 CSRF 時拒絕。此測試不使用 socket，不能代替真實瀏覽器／網路測試。

另模擬第二筆草稿寫入失敗，驗證整批交易撤回且操作鎖釋放，下一次批次仍可成功。可執行測試共 79 項通過；15 項需 socket 的測試仍受環境限制，GitHub 推送仍因無法解析 github.com 失敗。新版後端尚未重啟，不應宣稱本機網站已可使用批次操作。

## 三格式批次完整離線驗收

將原本真實 socket 全流程測試共用為兩種傳輸：一般 HTTP 連線與純記憶體 HTTP。兩者使用相同正式 request handler 與相同流程；原本 socket 版本仍保留，沒有用替代測試冒充連線成功。

新流程使用三種格式合成資料，依序加入版本與需求、模擬取得來源、檢查缺成本／匯率、填入報價、一次批次新增三件草稿、重送略過三件、修改草稿、拒絕來源版本錯配、產生 Sheets 資料與公式、匯出三列 CSV。全段通過。外部 Discogs／平台／Sheets 傳輸均使用測試替身，這次不代表真實市場或外部服務驗收。

可用下列命令重跑限制環境下的驗證；工具會明確列出未執行的 socket 測試，不把它們列為通過：

```sh
.venv/bin/python tests/run_offline.py
```
